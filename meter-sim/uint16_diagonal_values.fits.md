## Description

A minimal 3x3 image with three non-zero values (100, 1000, 65535) stored as 32-bit integers representing unsigned 16-bit data. Tests the FITS convention of storing unsigned 16-bit values in a signed 32-bit container.

The values lie on the anti-diagonal in storage order, not the main diagonal: in 1-based FITS pixel coordinates (x, y), 100 is at (1, 3), 1000 at (2, 2) and 65535 at (3, 1), and every other pixel is 0. The first stored row is `[0, 0, 65535]`, so a reader that indexes `data[0, 0]` gets 0, not 100. A bottom-left-origin viewer shows 100 at the top left and 65535 at the bottom right. This is consistent with the writer's vertical flip ([focalplane#77](https://github.com/CosmicFrontierLabs/focalplane/issues/77)).

## HDU Structure

| HDU | Type | EXTNAME | BITPIX | Dimensions | Content |
|-----|------|---------|--------|------------|---------|
| 0 | Primary | — | 8 | empty | Empty primary |
| 1 | IMAGE | UINT16_IMAGE | 32 | 3 x 3 | Anti-diagonal: 100 at (1, 3), 1000 at (2, 2), 65535 at (3, 1); 0 elsewhere |
