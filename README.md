# fits-test-cases

A curated collection of FITS files for regression testing FITS I/O libraries. Each file has a companion `.md` document describing its structure, provenance, and the FITS features it exercises.

## FITS Features Covered

- Primary HDU images (8/16/32/64-bit integer, 32/64-bit float)
- Image extensions (multiple per file)
- Binary table extensions
- ASCII table extensions
- Random groups format (deprecated, used in UVFITS)
- Tile-compressed images: RICE_1, GZIP_1, GZIP_2 (byte-shuffled), HCOMPRESS_1 (scale and smoothing) and PLIO_1
- Tile-compressed floats: quantization with `NO_DITHER` and `SUBTRACTIVE_DITHER_1`, global and per-tile `ZSCALE`/`ZZERO`, lossless GZIP floats, and the lossless GZIP fallback for unquantizable tiles
- Two-dimensional compression tiles, including clipped edge tiles
- A tile-compressed integer image with `BSCALE = 0.5`, and float tiles all stored in the lossless GZIP fallback under a `RICE_1` header
- `BLANK` nulls on scaled integer images, and a zero `BSCALE`
- Boolean columns
- Multi-dimensional arrays (3D cubes, 4D+ hypercubes)
- Unsigned integer images via BZERO
- HEALPix tables
- Multi-extension files (up to 15+ HDUs)
- Synthetic test patterns (gradients, checkerboards, Gaussian blobs)
- Extreme aspect ratio images (panoramic, columnar, single-row/column)
- Mixed data types within a single file
- CONTINUE long-string convention
- Array-in-cell binary table columns (repeat count > 1)
- AIPS-convention tables (AN, FQ)
- Random-groups UVFITS from casacore and cotter (and Birli, on the `mwa-v1` release), with `PZERO` on the `DATE` parameter
- Bit (`X`) columns, including a `1X` column written with integer values (not left-justified)
- Unsigned 16/32/64-bit and signed 8-bit table columns via `TZERO`
- `HIERARCH` keywords, including a `HIERARCH` long string
- `LONGSTRN`, and COMMENT/HISTORY text split across cards by cfitsio
- NUL-padded string cells and mixed-case column names
- Files over 2 GB with a table past byte 2³¹ (generated, not stored)
- Whole-file gzip compression (`.fit.gz`)
- `TZERO` offsets on table columns, including a double-precision time column
- Large binary tables (millions of rows)

## Usage

Each `.fits`, `.fit`, `.fit.gz`, `.uvfits`, `.metafits` or `.mwaf` file has a corresponding `.md` file named after the full file name. The markdown file documents:

- **Provenance**: Where the file came from and what instrument/survey produced it
- **HDU structure**: Number and types of HDUs, dimensions, data types
- **FITS features**: Which aspects of the FITS standard the file exercises
- **File size**: On-disk size

Small compressed images in `astroburst/`, `tile-compression/` and `refimage/` also have a `<name>.expected` file: astropy's decode of the image as little-endian `float64`, row-major, so a reader can be checked without astropy. cfitsio and fitsio-pure decode all 32 of these images to the same values.

## Contributing

To add a new test file:

1. Place it in the appropriate directory (or create a new one)
2. Add a companion `.md` file documenting the file's structure and provenance, written from the file's own header and data
3. Keep files under 50MB where possible
4. Copy the file byte for byte from its original source, and record that source. Moving a FITS file through anything that treats it as text corrupts it: five fixtures here were damaged that way before 2026-10-11.
5. Run `python3 scripts/check_fixtures.py`. CI runs it on every push and pull request. It walks every HDU of every fixture and fails on files that are not whole 2880-byte blocks, have headers off their block boundaries or non-ASCII bytes in headers, lack a `.md`, or are not marked binary in `.gitattributes`. A file that a tool really did write without final padding goes in its `ALLOW_UNPADDED` list, with the reason.
